# 📜 Antigravity AI 코딩 및 작업 규칙 (RULES.md)

이 파일은 이 프로젝트를 수행하는 모든 과정에서 AI 어시스턴트(Antigravity)가 반드시 준수해야 하는 최상위 지침입니다.

## 1. 언어 및 소통 원칙
- **전면 한국어 사용**: 모든 설명, 계획서(Implementation Plan), 작업 목록(Task), 완료 보고(Walkthrough)는 반드시 한국어로 작성합니다.
- **전문가 페르소나**: 최상위 ERP 전문가, 풀스택 웹 개발자, 그리고 감각적인 웹 디자이너의 관점에서 답변하고 제안합니다.

## 2. 기술 스택 및 구현 원칙
- **Core**: HTML5, Vanilla JavaScript (ES6+).
- **Styling**: Vanilla CSS 사용을 원칙으로 하며, 현대적이고 프리미엄한 UI(그라데이션, 글래스모피즘, 부드러운 트랜지션)를 구현합니다.
- **Backend**: 데이터 저장 및 실시간 동기화는 **Supabase**를 최우선으로 사용합니다.
- **AI Integration**: 로컬 모델은 **Ollama (gemma4:e4b)** 모델을 사용하며, `@local` 태그가 포함된 요청은 `LOCAL_PROTOCOL.md`를 따릅니다.

## 3. 디자인 및 UX 가이드라인 (Premium Aesthetics)
- **Visuals**: 단순한 MVP를 넘어선, 사용자에게 "Wow"를 줄 수 있는 고퀄리티 디자인을 유지합니다.
- **Theme**: 반드시 다크 모드(Dark Mode)를 기본 또는 선택 옵션으로 포함하며, 테마 전환 시 부드러운 시각적 효과를 제공합니다.
- **Typography**: `Pretendard` 또는 Google Fonts의 현대적인 서체를 사용합니다.
- **Interaction**: 호버 효과, 마이크로 애니메이션, 숫자 카운팅 애니메이션 등을 적극 활용하여 생동감 있는 인터페이스를 만듭니다.

## 4. 코드 품질 및 유지보수
- **시멘틱 HTML**: 의미에 맞는 HTML5 태그(`header`, `main`, `section`, `nav` 등)를 사용하여 SEO와 접근성을 높입니다.
- **주석 보존**: 코드 수정 시 기존의 주석이나 문서화된 내용을 임의로 삭제하지 않고 보존합니다.
- **모듈화**: 기능별로 로직을 분리하고, 재사용 가능한 컴포넌트 단위로 생각합니다.

## 5. 특정 작업 규칙 (가계부/복권/편의점)
- **정렬**: 모든 시간 관련 데이터는 단순 날짜가 아닌 '초' 단위까지 포함된 타임스탬프를 기준으로 최신순 정렬합니다.
- **알림**: 주요 변경 사항(데이터 저장/삭제)은 설정된 텔레그램 봇을 통해 알림을 전송하는 로직을 유지합니다.

## 6. 디자인 수정 요청 (2026-04-30)
사용자의 디자인 선호도 변경에 따라, 색상 팔레트를 **'차분하고 고급스러운 민트 그린(Mint Green)'** 계열로 전면 수정합니다.
- **Primary Color**: #008080 (Basic) -> #3cb371 (Mint Green) 계열로 변경.
- **Accent Colors**: #ff7f50, #ffd700 등 기존의 과감한 색상 대신, '#66cdaa' (MediumAquamarine) 등 차분한 톤을 사용합니다.
- **Visuals**: 심플하고 우아한 분위기를 유지하되, 필요한 곳에만 '포인트 색상(Mint)'을 사용하여 가독성과 심미성을 동시에 확보합니다.

## 7. 모바일 PWA 최적화 (2026-04-30)
모바일 환경에서의 사용성 극대화를 위해 **PWA(Progressive Web App)** 기능을 강화합니다.
- **홈 화면 설치 배너**: 사용자가 사이트에 방문했을 때 앱처럼 설치하라는 유도 배너를 노출합니다.
- **캐싱 전략**: Service Worker를 업데이트하여 오프라인 상태에서도 핵심 UI와 데이터가 빠르게 로드되도록 합니다.
- **네이티브 기능**: 지문 인식(Fingerprint)을 활용한 앱 잠금(App Lock) 기능을 추가합니다.

## 8. 사용자 경험 개선 (UX Improvement) (2026-04-30)
디자인 톤앤매너 변경(Rule 6)에 따라, 모든 화면 전환 및 입력 과정에서 사용자가 시각적/경험적으로 만족할 수 있도록 연출합니다.
- **입력창 애니메이션**: 텍스트를 입력할 때 타이핑되는 모션(Cursor Blink)과 입력 완료 시의 부드러운 페이드인(Fade-in) 효과를 추가합니다.
- **페이지 이동**: 페이지가 전환될 때 단순한 색상 변경이 아닌, 상단 헤더부터 스르륵 올라오거나(Slide Up) 좌우로 스르륵 지나가는(Slide Horizontal) 트랜지션 효과를 적용합니다.
- **전역 통일**: 본 프로젝트 내의 모든 페이지(가계부, 복권, 편의점)에 동일한 UX 원칙을 적용하여 일관성을 유지합니다.

## 9. 아이콘 디자인 통일 (2026-04-30)
프로젝트 전체의 시각적 완성도를 위해 모든 아이콘의 스타일을 '단색 라인 아이콘'으로 통일합니다.
- **형태**: 단순하고 세련된 2D 라인(Line) 스타일의 아이콘을 사용합니다.
- **색상**: 현재 정의된 컬러 팔레트(Mint Green 등) 내에서 통일감 있게 적용합니다.
- **제외**: 아이콘 전용 라이브러리(FontAwesome 등) 사용을 지양하고, SVG 또는 CSS 기반의 커스텀 아이콘 제작을 우선합니다.

## 10. 반응형 디자인 고도화 (Responsive Redesign) (2026-04-30)
현재의 3열 모바일 중심 디자인에서 벗어나, PC 및 태블릿 환경에서도 전문가적인 수준의 '가계부 대시보드' 경험을 제공해야 합니다.
- **레이아웃 전환**:
    - **Mobile (< 768px)**: 기존의 3열/카드형 레이아웃 유지.
    - **Tablet (768px ~ 1024px)**: 4열 또는 2x2 그리드 레이아웃으로 확장하여 정보 밀도를 높임.
    - **Desktop (> 1024px)**: 5열 이상 그리드 또는 메인 차트/데이터 테이블 중심의 와이드 대시보드 레이아웃을 구현.
- **그래프 스케일링**: 화면 크기에 따라 Y축(금액)의 표시 단위를 자동으로 조정하거나(Auto-Scaling), 차트의 두께/간격이 유연하게 변하도록 리팩토링.
- **전체 디자인 최적화**: 텍스트 크기, 마진, 패딩 값을 반응형으로 조정하여 어떤 기기에서도 가독성과 심미성이 유지되도록 합니다.

## 11. 인풋(Input) 처리 방식 개선 (2026-04-30)
모바일 환경에서 사용자가 금액이나 텍스트를 입력할 때 경험을 개선합니다.
- **자동 포커스(Auto-Focus)**: '금액 입력' 버튼(버튼 포함) 클릭 시, 즉시 입력창이 활성화되고 키보드가 올라와 사용자가 바로 입력할 수 있도록 합니다.
- **취소(Cancel) 로직**: 입력창 영역 밖을 클릭하거나 '취소' 버튼을 누르면 입력창이 부드럽게 사라지며(Fade Out) 입력 모드가 해제되어야 합니다.

## 12. 디자인 통일성 강화 (Style Unification) (2026-04-30)
프로젝트 내 모든 페이지(가계부, 복권방, 편의점)의 디자인 톤을 'Premium Mint' 테마에 맞춰 전면적으로 통일하고 고도화합니다.
- **색상 팔레트 적용**: 오직 '민트 그린(#3cb371)' 계열과 '#66cdaa', '#004d40' 등 모노크롬 그레이시 톤만을 사용합니다.
- **다크 모드 일관성**: 다크 모드(Dark Mode) 시에는 배경을 깊은 차콜 그레이(#1a1a1a) 또는 네이비 톤으로 설정하고, 텍스트와 카드에 #f0f0f0 ~ #ffffff의 화이트 톤을 적용하여 대비를 극대화합니다.
- **반응형 그리드**: 가계부 섹션에 더 많은 통계 및 그래프 카드를 배치할 수 있도록 반응형 그리드(Grid)를 확장합니다.
- **애니메이션 일관**: 모든 입력, 전환, 로딩 효과에 동일한 Easing 함수(예: ease-in-out)와 duration(예: 300ms)을 적용하여 통일감을 줍니다.

## 13. 데이터 무결성 및 보안 (Data Integrity & Security) (2026-04-30)
사용자의 소중한 금융 데이터를 안전하게 보호하고 데이터 처리 로직의 신뢰도를 높입니다.
- **사용자 인증(Auth) 적용**: 복권방 및 편의점 페이지에 Supabase Auth를 연동하여 로그인한 사용자만 접근 및 데이터 저장이 가능하도록 보안을 강화합니다. (가계부는 기본적으로 로그인 필요 없으나, 전체 통합 시 Auth 적용 고려)
- **RLS(Row Level Security) 정책**: Supabase 백엔드에 RLS 정책을 설정하여, 각 사용자가 자신의 데이터만 조회/수정할 수 있도록 제한합니다.
- **트랜잭션(Transaction) 처리**: 데이터 저장 시 네트워크 오류 등으로 인해 부분적으로만 저장되는 현상을 방지하기 위해, JavaScript 로직 또는 Supabase RLS 내에서 트랜잭션 처리를 검토하고 적용합니다.

## 14. 코드 구조 개선 및 파일 분리 (Code Refactoring & Organization) (2026-04-30)
유지보수성과 확장성을 위해 코드를 논리적인 단위로 분리하고, 데이터 로직을 중앙 집중화합니다.
- **Data Service 분리**: Supabase 통신 로직(CRUD 함수들)을 별도의 파일(예: `data-service.js`)로 분리하고, 각 페이지(index.js, lotto.js, store.js)는 필요한 함수만 import하여 사용하도록 리팩토링합니다.
- **전역 상수 및 설정**: API Key, 테이블명, 상수 값(예: 다크 모드 설정 값)을 별도의 파일(예: `config.js` 또는 `.env` 관리)로 분리하여 관리 용이성을 확보합니다.
- **모듈화**: 각 페이지의 뷰(View)와 로직(Controller)을 분리할 수 있다면 분리하여 가독성을 높이고, 순수 JavaScript(Vanilla JS) 원칙을 준수합니다.

## 15. 자동 삭제 타이머 (Auto-Delete Timer) (2026-04-30)
가계부 항목이 일정 기간(1년)이 지나면 자동으로 삭제되는 기능을 구현하여 데이터 관리를 자동화합니다.
- **로직 구현**: 데이터베이스 스키마(Schema)를 검토하여 `created_at` 등 날짜 필드를 활용하거나, 정기 실행 함수(Cron Job 등)를 통해 1년이 지난 모든 기록을 자동으로 삭제하는 백엔드 로직을 구현합니다.
- **사용자 알림**: 데이터 삭제가 실행되었을 때, 텔레그램 봇이나 화면 알림을 통해 사용자에게 "OOO 항목이 자동으로 삭제되었습니다"와 같이 알려주어 투명성을 확보합니다.
- **설정 옵션**: (선택 사항) 사용자가 '1년' 기준을 다른 기간(예: 6개월, 2년)으로 변경할 수 있는 설정 옵션을 제공합니다.
